# 一个人，也能像带团队一样推进多个项目

[English](product-highlights.en.md) · **简体中文**

> **把等待 AI 的时间，变成真正的并行产出。**

Caravel 不是又一个 AI 聊天窗口，也不只是多个 Agent 的启动器。它把 Claude Code、Codex、OpenCode、pi、Grok、TRAE 和 Antigravity 组织成一支可调度、可追踪、可干预、可验收的执行队伍。

你负责目标和判断，Agent 负责搜索、修改、验证和执行；只有遇到授权、业务决策和最终验收时，Caravel 才把注意力还给你。

## Caravel 带来的不是“多一个工具”，而是四种改变

### 把串行等待，变成并行推进

以前，一个终端跑一个任务：等它搜索、等它改代码、等它测试，中间还要不断切回去看有没有卡住。

现在，可以让不同 Agent 同时修 Bug、补文档、查数据、升级依赖和处理不同项目。Caravel 集中显示每个任务的状态，用户只处理真正需要介入的节点。

**同样一个小时，不是看一个 Agent 输出更多文字，而是让更多工作真正向前推进。**

### 把“AI 说完成了”，变成真正可以交付

AI 停止输出，不代表任务已经完成。代码是否正确、改动是否安全、最终能否进入项目，仍然需要清晰的交付过程。

Caravel 把目标、持续会话、执行计划、权限请求、代码 Diff 和验收结果放进同一个任务。Agent 可以在隔离副本或独立分支中大胆执行，用户看完改动后再决定合并、继续修改或放弃。

**完成不再是一句话，而是一份看得见、审得清、由你决定是否交付的结果。**

### 把一整套常驻工具，收进一个轻量工作台

日常派发、查文件、改配置、看 Markdown、查数据库、处理 Git 和审 Diff，可以直接在 Caravel 中完成。复杂调试和大型重构时，再按需打开 IDEA、VS Code 或其他专业工具。

近期 macOS 实测中，Caravel 通用版下载约 30 MB，基础运行内存约 170 MB；同机 IntelliJ IDEA 应用本体约 4.1 GB，尚未包含索引、插件和日志。

**不用为了改几行代码，先启动一个占用数 GB 内存并等待索引的 IDE。**

### 把一次成功，变成以后反复生效

大多数 AI 工具在对话结束后就失去了价值。Caravel 可以把高质量提示词、解决经验、专业技能和成功步骤继续沉淀下来。

一次成功对话可以提炼成工作流；稳定步骤可以变成本地脚本；周期工作可以交给定时器；多次任务可以生成带证据的复盘，再沉淀为新的经验和能力。

**Caravel 使用得越久，留下的不是更多聊天记录，而是一套越来越成熟的个人 AI 工作方法。**

## 1. 你不再管理终端，而是在管理工作

终端只能告诉你进程还在不在，Caravel 直接告诉你工作处于什么阶段。

- 哪些任务正在运行；
- 哪些任务等待权限或补充输入；
- 哪些任务已经完成执行、等待验收；
- 每个任务属于哪个项目、哪个 Agent 和哪个会话；
- Agent 当前计划、调用了什么工具、子 Agent 做到了哪里；
- 最后修改了哪些文件，结果是否已经交付。

列表适合快速扫描，看板适合观察流程，分屏适合同时盯住几个关键任务。终端可以继续作为接管入口，但不再承担项目管理职责。

## 2. 你的注意力只花在真正重要的地方

完全自动运行容易失控，保守模式又要求用户一直守着。Caravel 将“执行”和“决策”分开：

- 普通搜索、编辑和验证由 Agent 自主推进；
- 敏感操作和权限请求进入待确认；
- 需要业务判断时，Agent 可以向用户补充提问；
- 完成后的代码统一进入待验收；
- 用户可以停止、纠正、继续对话或转到终端接管；
- 离开电脑后，可以通过飞书查看进度、确认和验收；同一局域网的手机浏览器也能查看进度，并在电脑单独允许后处理授权、对话和验收。

用户不必观看 AI 工作的每一分钟，只需要出现在非你不可的时刻。

## 3. Agent 可以大胆执行，项目仍然保持可控

不同任务可以选择不同的运行边界：

- **直接工作区**：适合可信、快速的小任务，改动立即写入原目录；
- **隔离副本**：Agent 在独立副本中完成工作，通过验收后再合并；
- **独立分支**：同一任务可为多个 Git 项目分别创建副本和开发分支，汇总审查并逐仓库提交推送，不改动主工作区。

配合权限确认、代码 Diff、Git 操作和最终验收，Agent 的执行自由与项目安全不必二选一。结果不符合预期时，可以继续要求修改，也可以直接放弃整次改动。

## 4. 换 Agent、换时间，任务上下文仍然继续

终端关闭、应用重启或 Agent 不适合当前任务时，最浪费时间的是重新解释背景。

Caravel 按真实会话续接任务，被中断的运行会明确标记为待续接；原会话失效时可以建立新会话继续；切换 Agent 时，当前任务的目标和已有对话仍可作为上下文。

独立项目副本清理后保留恢复信息，续接时可在原路径恢复；即使任务记录已删除，也能从保留的新版副本创建新任务继续开发，原对话不会被伪造恢复。

你可以让不同 Agent 做它们各自擅长的事，而不是被某一个工具锁住。过去散落在 CLI 里的已有会话，也可以同步进任务库统一管理。

## 5. 代码、Git 和数据库不再是割裂的上下文

排查问题时，开发者经常在 IDE、终端、数据库客户端和 AI 对话之间反复搬运信息。Caravel 把这些高频能力放在任务旁边：

- 浏览、搜索和轻量编辑项目文件；
- 预览代码、Markdown、Mermaid、图片和版本差异；
- 查看分支、提交、推送、暂存和处理冲突；
- 查询 MySQL、PostgreSQL、SQLite、MongoDB 和 Redis；
- 通过 SQL Copilot 生成、解释、优化和修复查询，也可关联业务工作区，让 Agent 结合当前代码和数据库结构追踪业务口径，并核对引用的文件与行号；
- 在危险数据库操作前确认并尽可能展示影响范围；
- 经授权后通过 MCP 让 Agent 使用真实数据库上下文。

用户不必先把问题翻译成一大段 Prompt，再手工把查询结果复制回 Agent。

## 6. 重复工作可以离开你的日程表

日报、周报、代码扫描、依赖检查和数据巡检，不应该每次都靠人记得执行。

- 用一句话描述时间和任务，确认后创建定时器；
- 到点弹出提醒、运行本地脚本或派发 Agent；
- 让 Agent 首次生成并试跑脚本，以后确定性执行，不再重复消耗模型；
- 将 Agent、命令和人工确认编排为可重试、可跳转的工作流；
- 从一次成功任务中提炼工作流，下次直接复用。

自动化不只意味着“让 AI 再做一遍”，也可以把已经稳定的做法转成本地、便宜、可预测的执行。

## 7. 从想法出现，到 Agent 开始执行，中间不再断层

全局快捷浮窗可以立即添加待办、新任务或收件箱内容。待办能够携带标签、子项、图片和附件，也可以直接转换成 AI 任务，并跟随任务结果完成。

按需开启会话台后，不必先选择项目就能与 Agent 讨论需求、梳理想法并继续执行。会话保存在固定工作区，与项目任务分开展示，支持搜索、标签和置顶。

剪贴板保存文本、代码、JSON 和图片历史；“我的应用”则可以把一句具体需求变成日报助手、数据看板或个人小工具。

桌面小应用还可经授权连接本机脚本、文件、进程和本地服务，把常用操作做成可重复使用的工具；外观可跟随 Caravel，也可独立设计。本机授权支持按范围记住和撤销；程序执行具有当前用户权限，应只授予可信应用，不能视为进程沙箱。

用户不必先把想法记在一个应用、整理到另一个应用，再复制进第三个 Agent 窗口。

## 8. 数据和最终决定留在用户手里

任务、会话、工作区信息和个人知识资产由本机应用统一管理。Caravel 不要求注册自己的云账号，也不绑定单一 Agent。

用户继续使用自己的 Agent CLI、模型账号、Git 和 IDE，并自主决定是否启用飞书远程能力。更换 Agent 时，任务历史、提示词、经验和工作流仍然属于自己的工作体系。

本地优先不是为了让 AI 与网络完全隔绝，而是让用户清楚知道：什么保存在本机、什么由外部 Agent 处理、哪些权限由自己决定。

## 一个上午，可以这样工作

```text
09:00  给 Codex 派发后端 Bug，给 Claude Code 派发文档重构
09:05  自己继续处理需求，不再轮流盯两个终端
09:20  Caravel 提醒：一个任务需要权限，手机上确认继续
09:40  第一个任务进入待验收，查看 Diff 后要求补一个边界处理
10:00  第二个任务完成，在隔离副本中确认并合并
10:15  把这次成功的排查步骤提炼成工作流
下周    定时器自动运行同类检查，只在发现问题时通知你
```

真正的提升不是 Agent 打字更快，而是等待、切换、盯守和重复解释大幅减少。

## Caravel 适合谁

- 同时维护多个项目，希望在同一时间推进更多工作的开发者；
- 已经频繁使用 AI 编码，但受够了多个终端和会话混乱的用户；
- 希望 Agent 自主执行，同时保留权限和代码控制权的工程师；
- 需要重复执行代码检查、问题修复、数据巡检或发布流程的开发者；
- 希望把个人提示词、经验和成功流程积累成长期能力的重度用户；
- 关注 Agent 效率、成本和交付质量的技术负责人。

## 使用边界

- Caravel 仍需至少一个已经安装并完成配置的 Agent CLI；
- Antigravity 需要官方 CLI 和可用的账号或 API 配置；首次 ACP 连接可能需要独立浏览器登录；
- TRAE 需要 CLI 2.0 与企业版旗舰版账号；
- Git 工作区仍需 Git；
- 断点调试、性能分析、复杂类型导航和大型人工重构仍建议使用专业 IDE；
- Agent 访问模型服务时的数据处理方式，取决于对应 Agent 和模型供应商；
- Caravel 的价值不是彻底卸载所有开发工具，而是减少它们必须同时常驻的时间；
- 手机访问使用局域网 HTTP，只应在可信网络开启；任务操作默认关闭，链接外泄时关闭该开关或轮换链接。

## 开始把 AI 从聊天工具变成执行团队

1. 安装并登录至少一个受支持的 Agent CLI。
2. [下载 Caravel（macOS / Windows）](https://github.com/yy36295238/caravel-releases/releases/latest)。
3. 注册一个本地 Git 仓库或项目文件夹。
4. 创建任务、选择 Agent，然后继续做你自己的事。
5. Caravel 提醒你时，回来做确认、决策和验收。

**让 Agent 多写几行代码不是终点。用更少的注意力，稳定推进更多工作，才是 Caravel 真正的价值。**
